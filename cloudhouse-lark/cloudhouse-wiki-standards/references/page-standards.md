# 大云屋知识库页面样式标准

适用于飞书 Wiki 中新建或补写的首页、目录页、内容页、记录页。存量有实质内容的页面不强制改造；本标准的“新页面规则”与“存量页例外”分开执行。

## 1. 页面类型

| 类型 | 典型页面 | 核心目标 | 模板 |
|---|---|---|---|
| 首页 | 各空间“首页” | 说明空间定位、展示完整结构、提供全量入口 | `templates/homepage.xml` |
| 目录页 | 财务、行政、各组知识、管理员手册 | 用页面指引 + 彩色索引 + 结构图快速进入下级页面，保证不漏链 | `templates/directory.xml` |
| 内容页 | 制度、指南、工作流、学习路线 | 让读者能按步骤完成一件事 | `templates/content-scaffold.xml` |
| 记录页 | 负责人日志、近期待处理、会议记录 | 提供可追加的记录容器 | `templates/record-page.xml` |
| 容器页 | 已有填写说明的会议记录 | 只提供入口/规则 | 不重写 |

## 2. 标题与层级

- Wiki 节点标题是页面唯一标题；正文不再重复写一遍标题。
- 首页固定板块用 H1：愿景和目标、知识空间简介、常用文档和链接、知识空间帮助。
- 目录页、内容页、记录页从 H2 开始，子章节用 H3，最多到 H3。
- 存量内容页如果已经用 H1 重复标题，保持原样；新写/重写页面不沿用。
- 不使用跳级标题（H2 下直接 H4）。

## 3. 元数据与维护块

- **除索引页标识外，所有非首页页面都不写元数据 blockquote**（不写“文档权限/文档版本/维护人”）。
- 首页在页尾保留一行维护块：`文档版本：YYYYMMDD｜维护人：<角色>｜节点增减后请同步更新思维导图与索引表。`
- 目录页、内容页脚手架、记录页均不写维护说明、不写相关链接。
- 需要说明用途时，用一句普通段落，不包进 callout 或元数据块。

### 3.1 索引页标识

- 首页、目录页在 `<title>` 后的第一个块固定写 `<blockquote><p>本页为索引页</p></blockquote>`。
- 该提示位于欢迎 callout / 页面指引之前；不要用 callout 代替。
- 内容脚手架、记录页、内容页不加；已有提示的存量页保留，不重复插入。

## 4. 导语与 callout

- 内容页导语 1 句，只写标题可推导的定位，不写未经确认的制度事实。
- 目录页不使用 callout；标题后先放“本页为索引页”blockquote，再进入 H2“页面指引”。
- 内容脚手架、记录页不使用 callout；只用普通段落 + H2。
- 首页保留欢迎、使用帮助、维护约定 callout。
- Callout 只用实测稳定 emoji：📚 欢迎、💡 提示、📝 维护、🌱 上手。
- 颜色只用命名色：`light-blue`/`blue`、`light-yellow`/`yellow`、`light-green`/`green`、`light-gray`/`gray`。
- 每页 callout 不超过 3 个；不要用 callout 代替正文。

## 5. 表格

- 表头行放在 `<thead>`，单元格用 `<th background-color="light-gray" vertical-align="top">`。
- 目录索引表：
  - 平坦目录用两列：文档、说明。
  - 有分组用三列：分类、文档、说明。
  - 分组列只在每组第一行输出 `rowspan`，后续行不输出该列。
  - `rowspan` 之和必须等于数据行数；不要中途插空行。
- 首页索引表沿用现有三列（分类/文档/说明），表头背景 `light-gray`，分组色 `light-blue`/`light-orange`/`light-green` 轮换。
- 表格内不写长段落；每条说明控制在 30 字以内。
- 不编造说明里的数字、日期、负责人、金额。
- 单表数据行超过 80 行时，按分组拆成多张同结构表；每张表重复表头，分类列 rowspan 按该表内的组行数计算。300+ 行单表会触发飞书文档引擎 5000000 错误。
- 飞书会省略 `rowspan="1"`；回读校验时，三列且首格无 rowspan 的行按 1 计。

## 6. 链接

- 内链统一：`https://<tenant>.feishu.cn/wiki/<node_token>`。
- 链接文字用节点标题；节点标题有尾随空格时，显示文字可 trim，但链接 token 不变。
- 不要在索引表里用 `<cite>` 代替 `<a>`：`<cite>` 在批量校验时不便提取 token，`<a>` 更稳定。
- 跨空间链接也用完整 wiki URL；只在确有业务关系时添加。
- 外部链接用完整 URL；不猜域名、不编造文档地址。
- XML 文本中的 `&` 写 `&amp;`；`<` 写 `&lt;`；`>` 写 `&gt;`。

## 7. 命名与日期

- 不改存量节点标题。
- 新页面标题用“对象 + 类型”，2–12 字，例如“报销指南”“项目管理工作流”“实验室管理制度”；不带日期、版本号、emoji。
- 限定词用全角括号，例如“AI Coding考核指南（软件组）”。
- 会议记录沿用 `会议YYYYMMDD-负责人会议`。
- 正文日期用 `YYYY-MM-DD`；禁止“今天”“上周”“最近”等相对时间。

## 8. 空白页与待补充

- 纯空白页（正文 ≤12 字符）按页面类型补写；不得留空。
- 有效空白页（只有分节标题或 `TBD.`）保留原分节标题，补写脚手架。
- 脚手架顶部必须放 ⚠️ callout，明确：“本页为待补充脚手架，未确认的信息不在此页编造。”
- 每个空章节写“待补充：具体补什么”，用 checkbox 列提纲。
- 禁止裸 `TBD`、`TODO`、`待定`、`暂无`、`xxx`。
- 不编造人名、日期、金额、审批链、流程步骤、阈值、制度条款。

## 9. 首页规则

- 首页标题下第一个块是“本页为索引页”blockquote。
- 首页必须包含：欢迎 callout、愿景和目标、知识空间简介、Mermaid mindmap、全量索引表、使用/维护帮助、页尾维护块。
- 索引超过 80 行时按分组拆成多张表，计数句写“下方各表收录其余 N 个节点”。
- 计数句：“本空间共 **TOTAL** 个节点，其中首页 1 个；下表收录其余 **N** 个节点。”TOTAL/N 从实时节点树计算。
- 索引表覆盖全部非首页节点，包括 bitable 节点；bitable 用 `/wiki/<node_token>` 链接。
- mindmap 节点文本使用节点标题；含 `&` 的标题在 mindmap 中用“与”代替，索引表保留原名并转义。
- 首页已有实质内容时，只做精准编辑：保留快捷入口、愿景段落、已有 callout；只替换过时计数、链接、mindmap 和失效文字。
- 默认模板首页（含“在首页你可以对空间进行说明”）可以整体 `overwrite`。

## 10. 目录页规则

目录页固定三部分，顺序不可颠倒：**页面指引 → 子页面索引 → 页面结构图**。

- 标题下第一个块是“本页为索引页”blockquote，位于“页面指引”之前。
- H2“页面指引”：1–2 句说明本页汇总什么、读者怎么用；已有真实引言/链接时保留原内容。
- H2“子页面索引”：三列表（分类 / 文档 / 说明），列出全部后代节点。
  - 分类列按**直接子页**分组：每组第一行写 `rowspan`，分类单元格加背景色。
  - 颜色轮换：`light-blue` → `light-orange` → `light-green`；表头统一 `light-gray`。
  - 文档列用“└ ”前缀表示层级；说明列复用已有措辞，不编造业务事实。
- H2“页面结构”：Mermaid mindmap，根节点为本页标题，分支覆盖全部后代节点。
- 不写元数据块、目录说明 callout、维护说明、相关链接、返回首页链接。
- 不重复自身标题，不写空章节。
- 索引表数据行数 = 后代节点数；mindmap 分支节点数 = 后代节点数。
- 超过 80 行时分表；各表数据行之和 = 后代节点数。
- 索引用 `scripts/render_index.py`（directory 模式自带分组配色）；结构图用 `scripts/render_mindmap.py`。

## 11. 内容页脚手架规则

固定 3 个 H2，不写元数据、callout、相关链接、维护说明：

1. **页面定位**：一句话说明本页沉淀什么；不写具体制度内容。
2. **适用对象**：谁需要读/维护本页。
3. **待补充说明**：checkbox 提纲，列出需要负责人确认的章节。

正文目标 100–300 字；页面越短越好，不写重复的权限/版本/维护人。

## 12. 记录页规则

- 固定结构：一句使用说明段落 → H2 本期记录（表格）→ H2 待跟进（checkbox）。
- 不写元数据、callout、相关链接、维护说明。
- 记录表列建议：日期、事项、结果/状态、备注；待处理表可用：事项、负责人、截止日期、状态、备注。
- 空表放一行“待补充：从最近一次记录开始填写”，不要留纯空表。
- 不编造任何记录、任务、日期、负责人。
- 记录页不替代正式制度或会议纪要。

## 13. 存量页例外

以下情况不改：

- 有实质内容的制度、指南、手册、工作流。
- 有真实句子/链接但未补索引的薄页：运营、Agent、业务整理、建议/BUG反馈、实验室 Wi-Fi/值日/座位表等。
- 目录页如果已有真实引言/链接但缺索引，可保留原句，再补“子页面索引 + 页面结构”。
- 已有填写说明的容器页：会议记录。
- 失效节点：只报告，不重建。
- 节点标题：不改。
- 内容页即使有子节点（真题、附件、项目资料），也不按索引页改造；只在确有导航需要时由用户确认后追加索引。
- 空标题节点不写入索引/mindmap，报告中单列“未命名空白节点待整理”。

如果用户明确要求补写薄页，先按“有效空白”判断；只有正文确实没有实质信息时才允许重写。

## 14. 自检清单

- [ ] `<title>` 与 wiki 节点标题一致
- [ ] 正文没有重复标题
- [ ] 首页/目录页标题后第一个块是“本页为索引页”blockquote，且只出现一次
- [ ] 非首页页面没有元数据 blockquote、维护说明、相关链接
- [ ] 目录页只有“页面指引 / 子页面索引 / 页面结构”三个 H2，且顺序正确
- [ ] 目录索引表的分类列有 `rowspan` 和颜色，表头为 `light-gray`
- [ ] 内容脚手架只有“页面定位/适用对象/待补充说明”三个 H2
- [ ] 记录页只有“本期记录/待跟进”两个 H2
- [ ] 目录行数 = 实际后代数；首页行数 = 非首页节点数
- [ ] 多张分表时，各表数据行之和 = 预期行数，每表都有表头
- [ ] 目录结构图节点数 = 实际后代数
- [ ] 首页 mindmap 节点数 = 全部节点数
- [ ] 所有链接 token 存在且属于预期空间
- [ ] rowspan 与缺失单元格一致
- [ ] `&` 已转义；mindmap 无 ASCII 括号/引号/`&`
- [ ] 没有裸 `TBD/TODO/待定/暂无`
- [ ] 没有编造的人名、日期、金额、流程
- [ ] 有实质内容页未被 overwrite
